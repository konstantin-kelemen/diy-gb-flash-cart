## Задача и актуальная просьба пользователя

Исправить переполнение FPGA при сборке `game_programmer`, оптимизировать логику
и перенести часть задач режима PROGRAMMER на RP2040. Пользователь явно разрешил
изменить существующий протокол. Также попросил убрать хранение логотипа Nintendo
из FPGA: для определения MBC1M сравнивать области самого ROM; рассматривал хеш.

Реализация завершена и собирается для обоих устройств. На момент запроса этого
файла шла подготовка комплекта релиза, она ещё не завершена.
Последняя инструкция: **создать CONTEXT.md для другой машины, исходный код не менять**.
При подготовке этого файла исходный код не изменялся. Не считать эту просьбу
разрешением на дополнительную переработку кода или прошивку оборудования.

## Архитектура и решения

- FPGA: `LCMXO2-1200HC-4TG100C`, внутренний генератор 53.20 МГц, Diamond 3.14.
  Совмещённый target — `fpga/targets/game_programmer/top.v`.
- GAME остаётся автономным в FPGA: чтение ROM, мапперы, F-RAM, RTC и шина Game Boy.
  RP2040 не обслуживает игровые обращения в реальном времени.
- RP2040 в PROGRAMMER хранит буферы до 1024 байт, проверяет запросы USB,
  вычисляет CRC блоков, перебирает адреса, собирает прочитанные данные,
  пропускает запись байтов FF. Это убирает из FPGA блочные буферы и обработку блока.
- FPGA исполняет короткие команды SPI, аппаратные последовательности MX29LV320E,
  проверку Q5/тайм-ауты Flash, арбитраж общей шины и переключение режимов.
  Эти функции оставлены в FPGA ради детерминированных циклов шины.
- Внутренний протокол теперь **SPI v4**: Mode 0, MSB first, 4 МГц,
  защитные интервалы 2 мкс. Однобайтовые операции, результат через статус,
  CRC коротких кадров и ответов. Версия: `47 42 46 43 04 00 01 00`.
- Внешний USB CDC сохранён как GB3Q/GB3R v3, блоки до 1024 байт. Это решение
  реализации, а не требование пользователя о совместимости. SPI и USB sequence независимы.
- **Новые FPGA и UF2 использовать парой.** Новый RP2040 отклоняет SPI v3.
  Отдельный старый target `programmer` сохраняет SPI v3 через параметр RTL;
  для него нужна прежняя прошивка RP2040 из релиза v3.
- `programmer_block` параметризован: по умолчанию legacy v3, `HOST_BLOCKS=1`
  включает короткий v4. Совмещённый target по умолчанию выбирает v4.
- Команда `22` с key A5 удерживает PROGRAMMER на весь блок; `23` освобождает.
  При появлении питания Game Boy новые блоки запрещаются, текущий завершается.
  Физическое удержание снимается только после полного чтения ACK статуса
  (`02` + 10 dummy bytes и подъём CS). Частичное чтение не освобождает шину.
  Освобождение без действующего удержания возвращает ошибку 9 и не ставит pending.
- Watchdog удержания: `2^20` свободных тактов, около 19.7 мс. Во время Flash-операции
  счётчик сброшен, активная запись/стирание не прерывается. Истечение снимает armed.
  Перед передачей шины GAME выполняется read-array cleanup; при его ошибке GAME не стартует.
- RP2040 не повторяет разрушительную команду при потерянном ответе: операция
  могла выполниться. Сохраняет частичный completed, возвращает ошибку, закрывает armed.
  Полный тайм-аут запроса — 7 с.
- MBC1M определяется для MBC1 типов 1..3 и ROM-size 5 (1 МиБ): побайтовое
  сравнение всех 48 байт `0x000104..0x000133` и `0x040104..0x040133`.
  В FPGA только один текущий эталонный байт; константы логотипа и хеша нет.
  Совпадения областей целиком из 00 или FF отвергаются. Это эвристика, не проверка подлинности.
- RX CRC и CRC ответа используют общий последовательный 16-битный блок.
  Проверка входящего кадра — по нулевому остатку после принятых CRC-байтов.
  Ширины счётчиков уменьшены параметрами, статус выдаётся из снимка через byte mux.
- `mx29_programmer` использует уменьшенный op и таймер обратного отсчёта;
  `mx29_bus` вычисляет ширину счётчика по максимальному READ/WRITE_TICKS.
- `game_multi_core.bus_idle` — консервативный сигнал завершения сканирования и
  отсутствия RD/WR. Он убирает длинную цепь mapper decode из арбитража режима.
- Для `game_programmer` отдельная стратегия `GameProgrammerArea`, Area/53.20 MHz.
  Автоматическое продвижение локального reset на GSR отключено, в top есть GSR
  с константой 1. Иначе сброс Game Boy мог становиться глобальным сбросом FPGA.
  Финальная MAP-сборка содержит 0 GSR. Общая старая стратегия других targets сохранена.

Полный формат обмена: [docs/PROGRAMMER_SPI_V4.md](docs/PROGRAMMER_SPI_V4.md).

## Текущие ограничения и незавершённая работа

1. **Эта новая пара FPGA/RP2040 не испытана на плате и не прошивалась в оборудование.**
   Не переносить аппаратные PASS старых релизов v3 на этот вариант.
2. TRACE покрывает **88.48% соединений**. Асинхронные переходы из домена
   `gb_wr_n_c` не покрыты ограничением внутреннего clk. PAR предупреждает, что
   `gb_wr_n` на выводе 59 не является выделенным primary-clock входом и идёт через
   общую трассировку; возможны задержка/skew. Распиновка не менялась.
3. Скорость нового программатора не измерена. SPI-команда/статус на каждый байт
   экономит FPGA, но может замедлить чтение/запись. Это осознанный первый вариант.
4. CLI Diamond проверен полностью; GUI с новой стратегией отдельно не запускался.
5. **Упаковка релиза остановлена на создании манифестов.**
   В `releases/fpga/game_programmer/` сейчас только новый MANIFEST и **старый отчёт
   неудачного MAP** `RomEmu_game_programmer.mrp` (78506 байт). Его ещё не заменили.
   В `releases/rp2040/programmer-v4/` сейчас только MANIFEST.
   JEDEC/UF2/логи ещё не скопированы, `source/`, `SOURCE_SHA256SUMS.txt`,
   `SHA256SUMS.txt`, `artifact_check.txt` ещё не созданы.
   Манифесты уже описывают планируемый конечный комплект: ссылки и утверждение
   о проверке итогового UF2 пока нельзя считать выполненной работой.
6. Unit-тест генератора UF2 прошёл, но отдельная сверка **итогового собранного UF2**
   с BIN по всем блокам, адресам, family ID и padding ещё не выполнена.
7. Нет нового коммита. Значительная часть изменений уже staged, часть unstaged
   или untracked. Состояние индекса менялось извне во время работы; не сбрасывать его.

## Как продолжить

1. После переноса проверить `git status`, наличие всех перечисленных файлов и зависимостей.
   Сопоставить текущий код с этим контекстом: пользователь может продолжить менять дерево.
2. Завершить упаковку по правилам `releases/README.md`: скопировать финальные
   JEDEC/MRP/PAR/TWR и журналы в FPGA-комплект, UF2/ELF/BIN и журналы в RP2040-комплект.
3. Проверить итоговый UF2: заголовки каждого 512-байтного блока, payload 256,
   family ID, адреса от 0x10000000, номера/число блоков; восстановленный payload
   должен совпадать с BIN и нулевым дополнением последней страницы.
   Записать честный результат в `artifact_check.txt`.
4. Создать точный побайтовый снимок исходников FPGA/RP2040, constraints, скриптов,
   стратегий Diamond, тестов и документации в FPGA-комплекте `source/`.
   Учесть зависимости тестов: legacy programmer, game_multi и cart_mode.
   SDK/компиляторы/каталоги build туда не копировать. RP2040-манифест ссылается на общий снимок.
5. Завершить манифесты и вычислить SHA-256 всех файлов после окончательной записи.
   Указать базовый коммит и dirty snapshot; одного базового коммита недостаточно.
   Проверить ссылки и суммы. В `releases/` отключено преобразование переводов строк
   через `.gitattributes`, снимок должен сохранять точные байты.
6. Можно убрать только собственный временный эксперимент `fpga/diamond/Optimization.ldf`:
   он не нужен, не используется и пока untracked. Остальные файлы Diamond пользователя не трогать.
7. После согласованного аппаратного испытания проверить чтение/запись/стирание/verify,
   включение GAME в середине блока, пропадание RP2040, cold boot, MBC1M и игровые режимы;
   измерить скорость. Не объявлять аппаратный PASS без реального результата.

FPGA из корня репозитория (пути инструментов можно переопределить параметрами):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File fpga/targets/game_programmer/build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File fpga/tests/run.ps1
```

`-MapOnly` выполняет только синтез/MAP. Полная сборка проверяет строку
`Timing errors: 0 (setup), 0 (hold)` и только затем вызывает Bitgen.
Questa иногда возвращает exit 0 после `$fatal`, поэтому run.ps1 также требует
PASS-маркер и отсутствие ненулевого `# Errors:`. Нельзя судить только по exit code.

RP2040: ARM bin, CMake, Ninja и Python должны быть доступны, SDK содержит TinyUSB:

```sh
cmake -S firmware/rp2040/programmer -B firmware/rp2040/programmer/build-offload -G Ninja -DPICO_BOARD=waveshare_rp2040_zero -DPICO_NO_PICOTOOL=1 -DCMAKE_BUILD_TYPE=Release -DPICO_SDK_PATH=/path/to/pico-sdk
cmake --build firmware/rp2040/programmer/build-offload -j4
python -m unittest discover -s firmware/rp2040/programmer/tests -v
```

Для последней команды нужен нативный C-компилятор `cc` или переменная `CC`.
На предыдущей Windows-машине использовалось:

```powershell
$env:CC=(Join-Path (Get-Location) 'fpga/tests/build/tools/tcc/tcc.exe').Replace('\','/')
& fpga/tests/build/tools/python/python.exe -m unittest discover -s firmware/rp2040/programmer/tests -v
```

В конфигурации CMake также явно задавались абсолютные `CMAKE_MAKE_PROGRAM` и
`Python3_EXECUTABLE`. `PICO_NO_PICOTOOL=1` нужен для сборки без нативного C++-компилятора
для picotool; SDK всё равно формирует/checksum boot2, наш скрипт только упаковывает BIN.

## Важные детали для следующей сессии Codex

- До последней просьбы пользователь разрешал автономно продолжать оптимизацию и менять
  SPI-протокол; последняя просьба ограничивает текущую работу созданием документа без правок кода.
- Не сбрасывать индекс и не чистить массово рабочее дерево. Среди посторонних файлов
  есть `internal_rom.ccl`, `game_rom.ccl`, Diamond recovery/settings, `RomEmu_tcr.dir/`
  и результаты других targets. Это не мусор, который можно удалять по умолчанию.
- Не перепутать активный в IDE `internal_rom.ccl` с target задачи: оптимизировался
  **game_programmer**, а не internal_rom.
- Предыдущие эксперименты с асинхронными reset, комбинационным управлением Flash-шиной,
  изменённой фазировкой SPI были отменены. Их резервные файлы лежат в ignored
  `fpga/tests/build/`; они не являются актуальным исходником.
- Попытка отдельного Synplify-проекта не дала полезного результата; проверенный путь — LSE.
- В модели F-RAM была гонка delta-cycle, воспроизводившаяся и на исходном baseline.

- Финальные тесты уже пройдены; не повторять все долгие проверки без новой правки,

  не соответствует их полному описанию. Закончить упаковку или явно исправить статус
