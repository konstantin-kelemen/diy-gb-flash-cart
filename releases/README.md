# Выпуски

В этом каталоге хранятся сохранённые выходные файлы. Уровень проверки каждого
артефакта указан отдельно: здесь есть успешные и неуспешные FPGA-сборки,
а также UF2 без подтверждённого аппаратного испытания.

Каждый новый выпуск должен содержать манифест с именем конфигурации, исходным
коммитом, версией инструментов, контрольными суммами и результатами проверки
(для FPGA — также сводкой DRC и временного анализа). Если сборка сделана
с незакоммиченными изменениями, нужен точный снимок исходников с суммами:
одного базового коммита недостаточно.
Артефакт сборки нельзя считать проверенным на аппаратуре, если такая проверка
явно не зафиксирована в манифесте.

## FPGA

- [flash-bringup-fail](fpga/flash-bringup-fail/MANIFEST.md) — прежняя сборка с FAIL.
- [internal-rom-baseline](fpga/internal-rom-baseline/MANIFEST.md) — базовая
  проверенная конфигурация с внутренним ПЗУ.

## RP2040

[spi_bringup/gb_cart_rp2040.uf2](rp2040/spi_bringup/gb_cart_rp2040.uf2) —

содержит метаданные, SHA-256 и аппаратный результат: 1000/1000, PASS,
включая успешный повтор после выключения/включения питания. [Сборка из исходников](../firmware/rp2040/spi_bringup/README.md#сборка).

[programmer-v3](rp2040/programmer-v3/MANIFEST.md) — блочный программатор,
актуальный UF2 для протокола 3.0. Собран и проверен программно; аппаратная
приёмка не выполнена. [programmer v2](rp2040/programmer/MANIFEST.md) —
прежний несовместимый выпуск.

## Проверка контрольных сумм

Из корня репозитория:

```sh
cd releases/fpga/flash-bringup-pass
shasum -a 256 -c SHA256SUMS.txt
```

В `.gitattributes` для всего `releases/`, включая снимки исходников и
манифесты, отключено преобразование переводов строк. Файлы сохраняются
побайтово независимо от `core.autocrlf`.

В семи текстовых файлах `flash-bringup-pass` и отчёте `.pad` выпуска
`flash-bringup-fail` восстановлены исходные CRLF, подтверждённые опубликованными
SHA-256. Список сумм и манифесты сохранены без изменений. Проверены все суммы
из `SHA256SUMS.txt` и таблиц двух остальных FPGA-манифестов; расхождений нет.

Манифесты описывают состояние на момент выпуска. Их упоминания рабочего дерева
и следующих шагов относятся к тому испытанию; актуальный план — в
[документации проекта](../docs/README.md).

При подготовке нового выпуска сначала завершите его содержимое и манифест,
затем вычислите контрольные суммы. После добавления файлов в Git проверьте
суммы повторно на чистом checkout.
