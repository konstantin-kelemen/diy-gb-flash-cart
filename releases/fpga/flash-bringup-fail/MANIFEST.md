# Базовая конфигурация проверки внешней Flash

2026-09-06 проведена проверка внешней Flash на аппаратуре. JEDEC
и отчёты этой сборки сохранены в данном каталоге. Первоначальная оценка успеха исправлена:
тест провален. После исправления пинаута и повторной прошивки результат — **FAIL**.

**Реализация:** `flash_bringup`, верхний модуль `top`

**Микросхема FPGA:** `LCMXO2-1200HC-4TG100C`

**Flash:** MX29LV320E

**Инструмент:** Lattice Diamond 3.14.0.75.2

**Базовый коммит:**
`d909465968abc2fc8bafdef35926c2295e65aebd` (`Tested Flash memory, working`)

Текущая сборка использует рабочее дерево поверх этого коммита: поменяны
местами назначения `test_fail/test_pass` в `fpga/constraints/internal_rom.lpf`,
обновлены JEDEC и отчёты выпуска. Эти изменения пока не закоммичены;
`d909465` не является точной ревизией текущей сборки. После фиксации изменений
нужно записать новый коммит. Отчёт `.pad` также добавлен после базового коммита.

**Время сборки по отчётам Diamond:** 2026-09-06, Map 22:34:53,
TRACE 22:35:23, Bitgen 22:35:25. Часовой пояс в отчётах не указан.

## Исходные файлы

- `fpga/targets/flash_bringup/top.v` — автономная тестовая последовательность.
- `fpga/rtl/mx29_bus.v` — низкоуровневые циклы Flash.
- `fpga/diamond/RomEmu.ldf` — проект с реализацией `flash_bringup`.
- `fpga/constraints/internal_rom.lpf` — общий LPF с назначениями Game Boy
  и Flash, с исправленным пинаутом в рабочем дереве.

Отдельного исходного `flash_bringup.lpf` пока нет. В командной строке Map
также указан рабочий `fpga/diamond/flash_bringup/RomEmu_flash_bringup.lpf`;
его текущая локальная копия содержит только закомментированные строки.
При разделении LPF исходный выпуск и его отчёты нужно сохранить без изменений.

## Стенд и наблюдаемый результат

Использована Flash-память с контактами, выведенными на гребёнку.
LPF исправлен согласно исходному замыслу: `test_fail` — pin 83,
`test_pass` — pin 82. С новой прошивкой зафиксированы pin 83 — HIGH,
pin 82 — LOW: **тест провален**.

По `fpga/constraints/internal_rom.lpf` и сохранённому в выпуске отчёту
`RomEmu_flash_bringup.pad` вывод 83 — `test_fail`,
вывод 82 — `test_pass`. В `top.v` состояние `ST_FAIL` устанавливает
`test_fail=1`, `test_pass=0`; для `ST_PASS` уровни обратные.

Причина перехода в `ST_FAIL` пока неизвестна: итоговые два сигнала не
показывают, на какой операции произошёл сбой. Следующий шаг — добавить
диагностику этапа и данных ошибки, затем повторить испытание.
