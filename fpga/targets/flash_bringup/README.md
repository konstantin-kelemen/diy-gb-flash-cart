# Первичная проверка внешней Flash

Конфигурация состоит из:

- `top.v` — последовательность идентификации, стирания, записи и проверки;
- `../../rtl/mx29_bus.v` — низкоуровневые циклы параллельной шины.

Результаты испытаний — в [журнале](../../../docs/TEST_PLAN.md#журнал-результатов),
точный состав проверенной сборки и контрольные суммы — в
[манифесте выпуска](../../../releases/fpga/flash-bringup-pass/MANIFEST.md).

Сейчас проект ссылается на `../../constraints/internal_rom.lpf`, где уже есть
назначения Flash вместе с портами Game Boy. Перед следующей сборкой нужно
выделить назначения Flash в отдельный LPF и сверить их со стендом и схемой.
Это также устранит 54 предупреждения Map об отсутствующих портах Game Boy.

Внимание: `top.v` стирает выбранные секторы и записывает тестовые данные. До
запуска необходимо проверить адреса и ограничения выводов. Эта автономная
сборка начинает тест автоматически и не имеет входа выбора `GAME / PROGRAMMER`:
использовать её следует на отдельном стенде программирования с отключённым
Game Boy. В интегрированном программаторе выбор режима ещё предстоит реализовать.

## Сборка

Из корня репозитория открыть `fpga/diamond/RomEmu.ldf` в Diamond, выбрать
реализацию `flash_bringup` и верхний модуль `top`. Выполнить синтез, Map,
Place & Route и `Export Files -> JEDEC File`, как описано в
[общей инструкции](../../README.md#работа-в-lattice-diamond).
Результат: `fpga/diamond/flash_bringup/RomEmu_flash_bringup.jed`.
Для повторения сохранённого аппаратного опыта используйте JEDEC из выпуска;
результат новой сборки требует собственной проверки.

## Диагностика этапа сбоя мультиметром

Диагностика присутствует в текущем исходнике и выпуске `flash-bringup-pass`;
в сохранённом `flash-bringup-fail` её нет.

После ошибки pin 82 (`test_pass`) остаётся LOW, а pin 83 (`test_fail`)
выдаёт повторяющиеся группы импульсов. Один импульс: около 2 с HIGH и
2 с LOW. После последнего импульса LOW длится около 10 с суммарно.
Мультиметр подключается между pin 83 и GND в режиме измерения постоянного
напряжения. Нужно дождаться длинной паузы и посчитать подъёмы напряжения
в следующей полной группе; подтвердить число по второй группе.

| Импульсов | Место сбоя |
|---|---|
| 1 | ID производителя не равен ожидаемому в тесте `C2` |
| 2 | ID устройства не равен ожидаемому в тесте `A7` или `A8` |
| 3 | Начало одного из стираемых секторов прочитано не как `FF` |
| 4 | Ошибка сравнения одного из 16 шаблонов данных |
| 5 | Опорный адрес `010000` прочитан не как `A5` |
| 6 | Ошибка сравнения одной из 22 адресных проб |
| 7 | Недопустимое состояние тестового автомата |

При успехе pin 82 постоянно HIGH, pin 83 постоянно LOW. Пока тест выполняется,
оба вывода LOW; штатная последовательность занимает около 18 с.
Пауза LOW внутри кода ошибки не означает успех. После FAIL новые команды
Flash не выдаются; группа повторяется до перезапуска питания.

Код определяет проверку, обнаружившую ошибку, но не доказывает физическую
неисправность соответствующей линии. Фактические прочитанные байты и адрес
пока не выдаются. После определения кода можно сузить следующий эксперимент.

## Проверка диагностики

Добавлен тест `fpga/tests/flash_bringup_tb.sv` с моделью команд и памяти,
сценарием PASS, шестью ошибками чтения и недопустимым состоянием.
Проверяются две полные группы каждого кода, стабильность PASS и отсутствие
новых команд памяти после завершения. Временные задержки в симуляции сокращены.
Это функциональная проверка, а не модель электрических параметров MX29LV320E.

Запуск из корня репозитория с установленной Questa Lattice OEM Edition:

```powershell
New-Item -ItemType Directory -Force fpga/tests/build | Out-Null
Set-Location fpga/tests/build
& C:/lscc/diamond/3.14/questasim/win64/vsim.exe -c -do ../flash_bringup.do
```

## Стартовый сброс и проверка netlist

Четыре примитива `FD1S3AX` формируют явный синхронный сброс на первых четырёх
тактах для тестового автомата, контроллера шины и диагностики.
История ошибки начального состояния приведена в журнале испытаний.

Добавлен `fpga/tests/flash_startup_netlist_tb.sv`: используется схема LSE
`top_prim.v` и библиотека Lattice `ovi_machxo2`, а не RTL-модель `initial`.
Подтверждены завершение стартового сброса, начальная задержка и неактивная
шина Flash. Из `fpga/tests/build` после синтеза:

```powershell
& C:/lscc/diamond/3.14/questasim/win64/vsim.exe -c -do ../flash_startup_netlist.do
```

В модели сгенерированной схемы остаются предупреждения о неподключённых
неиспользуемых входах LUT. Функциональные проверки завершились без ошибок.
Симуляция RTL отдельно покрывает всю последовательность теста и коды ошибок.
