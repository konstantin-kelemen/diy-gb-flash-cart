# LSDj: MBC5 и F-RAM

Отдельная GAME-конфигурация для `roms/lsdj9_4_2.gb`: 1 МиБ ROM,
заголовок `1B 05 04`, 128 КиБ RAM. RTL проверен; сборка Diamond,
post-route timing и запуск на Game Boy ещё не выполнены.
Соединения хранятся в [схеме KiCad](../../../hardware/cartridge/cartridge.kicad_sch).

## Поведение

Регистры соответствуют [MBC5 / Pan Docs](https://raw.githubusercontent.com/gbdev/pandocs/master/src/MBC5.md):
фиксированный банк 0 в `0000–3FFF`, переключаемый банк в `4000–7FFF`,
RAM в `A000–BFFF` при активном CS#. Банк ROM 0 допустим в обоих окнах.
Запись в `2000–2FFF` задаёт младшие 8 бит, в `3000–3FFF` — девятый бит.
Физически используются только младшие 6 бит: образ 1 МиБ зеркалируется.

Запись в `0000–1FFF` разрешает RAM, если младшая тетрада равна A;
остальные значения запрещают RAM. В `4000–5FFF` выбирается один из
16 банков RAM младшей тетрадой данных. Rumble отсутствует.
После конфигурации и при RESET# LOW: банк ROM 1, RAM 0, RAM запрещена.
Регистры принимают данные на положительном фронте WR# при RD# HIGH.
Неиспользуемые записи игнорируются. Чтение запрещённой RAM возвращает FF.

Flash WE# постоянно HIGH. Памяти выбираются взаимоисключающе, FPGA
выдаёт данные на общую шину только при записи RAM. Вход преобразователя
Game Boy остаётся включённым между транзакциями и после WR#, чтобы не
обрезать удержание данных при записи регистров. При чтении направление
меняется к Game Boy; при сбросе преобразователь отключён.

F-RAM CE# активен только на время обращения RD#/WR# и отпускается между
ними. Это обеспечивает отдельный цикл precharge, если длительность паузы
соответствует [FM28V100, стр. 8–11](https://www.infineon.com/assets/row/public/documents/10/49/infineon-fm28v100-1-mbit-128k-x-8-f-ram-memory-datasheet-en.pdf).
Для 3,3 В требуются CE# LOW не менее 60 нс, precharge не менее 30 нс,
WE# LOW не менее 18 нс, setup данных записи не менее 15 нс.
RTL не растягивает внешние импульсы и не содержит внутреннего генератора.

## Проверка на Mac

Из корня проекта с установленным Icarus Verilog:

```sh
iverilog -g2012 -Wall -s game_mbc5_tb -o /tmp/game-mbc5.vvp fpga/targets/game_mbc5/top.v fpga/tests/game_mbc5_tb.sv
vvp /tmp/game-mbc5.vvp
python3 -m unittest discover -s host/tests -v
```

Покрытие и результаты — в [журнале испытаний](../../../docs/TEST_PLAN.md#журнал-результатов).
Модель: Flash 70 нс, F-RAM 90 нс, преобразователь 5 нс; чтение проверяется
через 160 нс. Проверяются длительности CE#/WE#, precharge и setup данных.
Host-тест выполняет два полных чтения 4 МиБ и запись LSDj между ними
для Top/Bottom Boot; при отсутствии локального ROM используется синтетический
образ того же размера. Это симуляция, аппаратные дампы не создаются.

## Сборка в Windows

Открыть `fpga/diamond/RomEmu.ldf`, выбрать **game_mbc5**, верхний модуль `top`.
Выполнить синтез, Map, Place & Route, TRACE и экспорт JEDEC.
Ожидаемый путь — `fpga/diamond/game_mbc5/RomEmu_game_mbc5.jed`.
Для записи Flash отдельно собрать обновлённый **programmer**;
RP2040 `programmer-v3` и текущая утилита Mac совместимы без изменения протокола.
Старый JEDEC `releases/fpga/programmer-v3/` не подходит для подключённой F-RAM.

LPF фиксирует выводы и электрические стандарты. Временные требования пока
не закрыты; отсутствие ошибок TRACE без заданных внешних требований
не является PASS. Проверить `.pad` по [процедуре](../../../docs/TEST_PLAN.md#сверка-lpf).
Проверить задержки адреса к памяти, RD#/WR#/CS# к CE#/OE#/WE#, памяти
к Game Boy, Game Boy к F-RAM и setup/hold регистров относительно WR#.
Учесть преобразователи, разводку, выключение выходов памяти и смену DIR,
hold данных относительно конца WE#/CE#, reset recovery/removal и старт F-RAM.
Поддержка ускоренного режима GBC аппаратно не подтверждена.
