# SPI bring-up

Отдельная конфигурация MachXO2 для запроса версии с RP2040-Zero.
Реализован [протокол 1.0](../../../docs/SPI_BRINGUP.md): Mode 0, 10 кГц,
команда `01`, ответ `47 42 46 43 01 00 00 00`. Первый байт MISO — нулевой.
CS# должен оставаться низким на протяжении всех девяти байт.
Перед первым запросом после конфигурации выдержать 1 мс с CS#=1 и SCK=0.

Входы проходят двухступенчатую синхронизацию на внутренние 2,08 МГц.
На старте используется явная цепочка FD1S3AX. Частота SPI выше 10 кГц
не входит в проверенный режим. Задержки CS# — не менее 20 мкс по протоколу.

Flash CE#/OE#/WE# постоянно HIGH, адрес равен нулю, D-шина освобождена
и её подтяжки отключены. Game Boy при этом эксперименте отключён.
Данные Flash не читаются и не изменяются.

## Выводы

| Сигнал | FPGA TQFP100 | RP2040-Zero |
|---|---|---|
| MOSI | 96 | GP3 |
| CS# | 97 | GP1 |
| SCK | 98 | GP2 |
| MISO | 99 | GP0 |
| spi_ready | 82 | — |
| spi_seen | 83 | — |

**Индикация отличается от Flash-теста.** Pin 82 поднимается после стартового
сброса. Pin 83 поднимается после 72 тактов кадра GET_VERSION и остаётся HIGH
до перезапуска FPGA. Это признак отправленного ответа, а не подтверждение
его правильного приёма RP2040. Неизвестные и неполные запросы не устанавливают
этот признак; уже установленный признак они не сбрасывают.

## Сборка

В Diamond открыть `fpga/diamond/RomEmu.ldf`, выбрать implementation
`spi_bringup` и выполнить экспорт JEDEC. Автоматически выбранная прежняя
implementation проекта не менялась: перед сборкой проверить выбор.

Альтернативно, из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File fpga/targets/spi_bringup/build.ps1
```

Параметр `-DiamondRoot` позволяет указать каталог Diamond; по умолчанию
`C:/lscc/diamond/3.14`. Результат:
`fpga/diamond/spi_bringup/RomEmu_spi_bringup.jed`.
Рядом формируются отчёты `.pad`, `.mrp`, `.twr` и `.bgn`.

## Проверка

Из `fpga/tests/build` (создать каталог при первом запуске):

```powershell
& C:/lscc/diamond/3.14/questasim/win64/vsim.exe -c -do ../spi_bringup.do
& C:/lscc/diamond/3.14/questasim/win64/vsim.exe -c -do 'set netlist 1; do ../spi_bringup.do'
```

Вторая команда требует предварительной сборки: используется `top_prim.v`
и библиотека примитивов MachXO2. Обе проверки моделируют обмен через внешние
порты: старт, сигнатуру, 71 длину прерванного кадра, неизвестную команду,
лишние байты за пределами счётчика и восстановление следующим запросом.
Проверяются освобождение MISO и неактивность Flash.

2026-09-07: RTL и netlist — PASS; Map — без ошибок и предупреждений,
39/640 SLICE; timing setup/hold — 0 ошибок на 2,08 МГц.
Предупреждения LSE относятся к постоянному биту ответа и отсутствию
генерируемого LPF (Map получает отдельный LPF проекта). Предупреждения
симуляции netlist относятся к незадействованным входам примитивов.
Проверка времён не заменяет аппаратную проверку асинхронного SPI.

**Аппаратная проверка ещё не выполнена.** Для неё нужна прошивка RP2040:
1000 правильных ответов на ПК, затем повтор после отключения питания.
Этот JEDEC пока не является проверенным аппаратным релизом.
