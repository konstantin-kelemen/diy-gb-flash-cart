# Документация

## Приоритет источников

Единственный нормативный источник электрических соединений —
`hardware/cartridge/cartridge.kicad_sch`.

При расхождении артефакты проверяются в следующем порядке:

1. схема картриджа — соединения и номиналы установленных компонентов;
2. PCB картриджа — размещение и трассировка;
3. ограничения FPGA и константы прошивки — должны соответствовать схеме;
4. сгенерированные перечни компонентов и отчёты по назначениям выводов;
5. пояснительная документация.

Документы могут кратко пересказывать схему, но не должны заново определять её
соединения.

## Состав документации

- [STATUS.md](STATUS.md) — проверенные, реализованные и запланированные части.
- [ARCHITECTURE.md](ARCHITECTURE.md) — границы подсистем и требования безопасности.
- [ROADMAP.md](ROADMAP.md) — порядок первичной проверки и критерии готовности.
- [TEST_PLAN.md](TEST_PLAN.md) — обязательные проверки и сохраняемые результаты.
- [SPI_BRINGUP.md](SPI_BRINGUP.md) — подключение RP2040-Zero и протокол первого обмена.
- [BOM.md](BOM.md) — заметки по комплектации; не источник электрической истины.

`archive/` содержит устаревшие снимки, оставленные только для истории. Они не
должны использоваться при проектировании или закупке.

## Как поддерживать документацию

- Текущий статус хранится в `STATUS.md`, хронология испытаний — в `TEST_PLAN.md`.
- `ROADMAP.md` содержит этапы и критерии; `ARCHITECTURE.md` — общие требования.
- Подключение стенда и формат SPI описываются только в `SPI_BRINGUP.md`.
- README конфигурации содержит сборку, запуск и специфическую диагностику.
- Манифест выпуска фиксирует его исходники, инструменты, отчёты и контрольные суммы.

В остальных местах используйте ссылки вместо копирования таблиц, результатов
и протокола. Исторические манифесты и снимки исходников не актуализируются
вместе с текущим кодом. README нужен каталогу с собственной инструкцией или
навигацией; промежуточные каталоги не требуют отдельных заглушек.
