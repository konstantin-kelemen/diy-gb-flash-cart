# Программатор: USB и SPI v5

[Практическая инструкция на Mac](PROGRAMMER.md). FPGA `game_programmer`,
RP2040 `programmer` 5.0 и `host/gbflash.py` v5 обновляются совместно.
Автоматической совместимости с прежними версиями нет. Отдельный target
`programmer` сохраняет [SPI v3](PROGRAMMER_PROTOCOL_V3.md);
[описание SPI v4](PROGRAMMER_SPI_V4.md) относится к старым выпускам.

## Архитектура и производительность

Mac передаёт блоки 1..16384 байта. RP2040 проверяет весь USB-кадр,
делит блок на порции 1..256 байт и агрегирует результат. FPGA принимает порцию
в общий буфер 256×8 с атрибутом `block_ram`; запись начинается только после
проверки CRC и точной длины кадра. Фактическое размещение в одной EBR требует
подтверждения MAP. Для чтения FPGA заполняет этот же буфер, затем выдаёт его
по SPI с CRC. Адрес увеличивается в FPGA без запросов RP2040 на каждый байт.
Запросы последовательные; одновременно исполняется одна порция.

Полный дамп — 256 USB-запросов и 16384 SPI-порции. Передача полезных 4 МиБ
при SPI 4 МГц занимает теоретически 8,39 с. Цель полного чтения — до 20 с;
фактическая скорость v5 на аппаратуре не измерена. Стирание и физическое
программирование Flash добавляют своё время. DMA, изменение частоты SPI и
сокращение импульсов Flash в v5 не применяются.

## USB CDC

Кадр: `GB5Q length_be16 payload crc32_le` для запроса,
`GB5R length_be16 payload crc32_le` для ответа. Длина учитывает только payload;
максимум — 16392 байта в обоих направлениях. CRC-32/ISO-HDLC покрывает два
байта длины и payload: reflected polynomial `EDB88320`, init/xorout `FFFFFFFF`.
Контрольный вектор `123456789` → `CBF43926`; в кадре `26 39 F4 CB`.
Данные бинарные; преобразование переводов строк отключено.

Одиночный payload `01` запрашивает версию. RP2040 сначала проверяет SPI v5,
затем возвращает `47 42 46 43 05 00 00 40`: GBFC, версия 5.0,
максимальный USB-блок `4000` little-endian. При несовместимой FPGA — ошибка E1.
Одиночный `02` возвращает последнее состояние RP2040; из него утилита берёт
текущий USB sequence. SPI sequence независим и читается из FPGA.

Запрос операции: `op sequence address_be24 length_be16 key [data]`.
Внутреннего CRC в USB payload нет. Данные присутствуют только для `31`.

| op, hex | Назначение |
|---|---|
| 30 | Читать 1..16384 байта, ARM не требуется |
| 31 | Записать 1..16384 байта, данные той же длины, требуется ARM |
| 12 | Стереть сектор, требуется ARM |
| 13 | Прочитать ID, требуется ARM |
| 14 | Вернуть read-array, требуется ARM |
| 20 | ARM: address=0, length=0, key=A5 |
| 21 | LOCK: address=0, length=0, key=0 |

Для остальных управляющих операций length=0; key=0, кроме ARM.
Адреса байтовые `000000..3FFFFF`, диапазон блока целиком внутри Flash.
Sequence увеличивается modulo 256; повтор последнего sequence отклоняется.

Ответ операции — `op sequence status result_lo result_hi completed_lo completed_hi 00`.
Успешное чтение добавляет ровно `length` байт. SPI-состояния и SPI CRC в USB-ответ
не копируются: RP2040 проверяет их сам. ID возвращается как C2 и A7/A8 в result.
`completed` суммируется по порциям, включая пропущенные FF. У управляющих
операций ID/reset/erase он равен 1 при успехе, у ARM/LOCK — 0.

Статусы 00..0A совпадают со SPI. Ошибка Flash внутри порции возвращается с
точным префиксом выполненных байтов; её адрес — `address + completed`.
При транспортной ошибке число подтверждённых байтов не определяет, сколько
байтов реально записалось после последнего полученного подтверждения.

| Код, hex | Ошибка моста |
|---|---|
| E1 | Несовместимая версия SPI или неверный CRC/формат SPI-ответа |
| E2 | Неверный USB-кадр, CRC, длина или запрос |
| E3 | SPI занят, режим/удержание недоступны либо повтор USB sequence |
| E4 | Истёк срок обработки |
| E5 | Некорректный счётчик выполненных SPI-байтов |

Ошибки при разборе кадра, повтор USB sequence и ошибка запроса версии могут
возвращаться одним байтом вместо состояния. Остальные ошибки возвращаются
в состоянии с op/sequence. При ошибке снимается разрешение записи на RP2040;
для продолжения записи требуется новое ARM. Никакие команды автоматически
не повторяются: ответ мог потеряться уже после изменения Flash.

## SPI

Mode 0, MSB first, 4 МГц. CS# низкий на весь кадр, защитные интервалы перед
первым фронтом, после последнего спада и между кадрами — не менее 2 мкс.
Запрос: `op sequence address_be24 length_be16 key [data] crc16_be`.
Максимум — 266 байт. CRC-16/CCITT-FALSE покрывает заголовок и данные:
polynomial `1021`, init `FFFF`, без отражения, xorout 0. Контрольный вектор
`123456789` → `29B1`. FPGA проверяет нулевой остаток всего принятого кадра.

Команды 12/13/14/20/21/30/31 имеют описанное выше назначение, длина блока
на SPI ограничена 256 байтами. Дополнительно:

- `22`, address=0, length=0, key=A5 — получить удержание PROGRAMMER.
- `23`, address=0, length=0, key=0 — освободить удержание.
- `01` + 8 dummy — версия `47 42 46 43 05 00 00 01` (максимум 256 LE).
- `02` + 10 dummy — снимок `50 sequence flags_status op result_lo result_hi
  completed_lo completed_hi crc_hi crc_lo`; CRC покрывает первые 8 байтов.
- `03` + `length+2` dummy — буфер последнего успешного чтения с CRC данных.
  Использовать до освобождения удержания и до следующей операции.

В `flags_status`: младшие 4 бита — статус, `80` — удержание,
`40` — разрешён приём следующей порции. Статусы: 0 успех, 1 занят,
2 неизвестная операция, 3 timeout, 4 Q5, 5 readback mismatch,
6 ошибка контроллера, 7 CRC, 8 адрес/длина, 9 блокировка, A повтор sequence.
Операции Flash требуют удержания; все изменяющие команды и ID/reset требуют ARM.
FPGA проверяет Q7/Q5, завершает read-array reset и останавливается на первой
ошибке. Запись FF пропускается только в сценарии с проверенным стиранием.

## Режимы и тайм-ауты

RP2040 получает удержание перед каждой порцией или управляющей операцией Flash.
После результата и выгрузки данных он отправляет `23` и читает полный статус.
В ответе на `23` бит `80` уже снят, но шина физически удерживается до конца
полного чтения состояния (`02` + 10 dummy). Частичное чтение не освобождает шину.
Появление питания Game Boy запрещает следующую порцию, но не обрывает принятую.
Незавершённый USB-блок возвращается с ошибкой. Перед GAME выполняется cleanup;
при его ошибке GAME не включается. F-RAM и CPU изолированы в PROGRAMMER.

Watchdog удержания — `2^20` свободных тактов (~19,7 мс при 53,2 МГц).
Во время исполнения Flash счётчик сброшен. Потеря RP2040 не обрывает запись
или стирание; после освобождения снимается ARM.

Приём USB-кадра ограничен 2 с, включая непрерывно поступающие байты.
После ошибки вход отбрасывается до 100 мс тишины без поиска magic в payload.
Перед подключением утилита ждёт 2,2 с и очищает входной буфер.
На SPI-порцию с получением/освобождением удержания отведено до 7 с;
на весь USB-запрос — до 90 с. Утилита ждёт ответ до 120 с суммарно,
с единым сроком для заголовка и данных. Эти пределы не являются оценкой скорости.

## Flash и внешние тайминги

OSCH — 53,20 МГц, `READ_TICKS=4`, `WRITE_TICKS=32`. При 64 МГц интервал
от OE#/CE# до выборки — 187,5 нс, длительность WE# LOW — 500 нс.
Таймеры: старт 16 млн тактов, program 128 тыс., erase 192 млн;
при 53,2 МГц — примерно 301 мс, 2,4 мс и 3,6 с. Общий контроллер Flash
и его алгоритм Q7/Q5 не изменены.

RTL-модели проверяют задержки Flash и F-RAM; реальные post-route пути,
разброс OSCH, задержки преобразователей уровней и монтаж требуют отдельной
проверки. Успешный внутренний TRACE не подтверждает внешние тайминги.
[Сборка и проверки](../fpga/targets/game_programmer/README.md).
