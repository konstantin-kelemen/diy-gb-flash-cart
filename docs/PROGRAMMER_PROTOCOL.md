# Программатор: блочный протокол 3.0

[Порядок работы на Mac](PROGRAMMER.md). Версия 3 несовместима с v2;
UF2 и FPGA обновляются вместе. Размер блока — 1..1024 байта. Память адресуется
байтами, диапазон `000000..3FFFFF`. Все числа ниже, кроме длин, — hex.

## SPI

Mode 0, MSB first, 4 МГц, CS# остаётся низким весь кадр.
Интервалы до первого фронта, после последнего спада и между кадрами — ≥2 мкс.
После запуска RP2040 выдерживается 400 мс. FPGA не выдаёт стартовых команд Flash.

Запрос операции:

```text
command sequence address_hi address_mid address_lo length_hi length_lo key
[payload: length bytes, только WRITE_BLOCK]
crc_hi crc_lo
```

CRC-16/CCITT-FALSE: polynomial 1021, init FFFF, без отражения/xorout.
CRC охватывает заголовок и payload. Запрос исполняется только после снятия CS,
если длина точна, CRC верен, FPGA свободна и sequence отличается от предыдущего.
Sequence увеличивается modulo 256; после подключения сначала читается текущий.
Кадры, начатые во время busy, игнорируются целиком. Неполные и лишние кадры
не исполняются. При ошибке CRC или повторе sequence снимается ARM.

| Command | Назначение |
|---|---|
| 30 | READ_BLOCK: length=1..1024, без payload; обычное чтение разрешено без ARM |
| 31 | WRITE_BLOCK: length=1..1024, payload той же длины; требуется ARM |
| 12 | Стереть сектор по address; length=0, требуется ARM |
| 13 | Прочитать ID и вернуть Flash в read-array; length=0, требуется ARM |
| 14 | Reset/read-array F0; length=0, требуется ARM |
| 20 | ARM: address=0, length=0, key=A5 |
| 21 | LOCK: address=0, length=0, key=0 |

В остальных запросах key=0. WRITE_BLOCK буферизуется целиком до проверки CRC.
FPGA программирует байты последовательно, с Q7/Q5 polling, тайм-аутом и
проверкой прочитанного байта. FF пропускаются; утилита предварительно проверяет
полное стирание затронутых секторов. Аппаратного многобайтового программирования
самого чипа этот протокол не предполагает. На первой ошибке блок останавливается,
ARM снимается, префикс уже записанных байтов сохраняется.

### Запросы ответов

Первый принятый байт, одновременно с opcode, отбрасывается RP2040.
После opcode передаются нулевые dummy bytes:

- `01` + 8 dummy → `47 42 46 43 03 00 00 04`: GBFC, версия 3.0,
  максимальный блок 0400, little-endian.
- `02` + 10 dummy → снимок статуса с CRC:

  ```text
  50 sequence status command result_lo result_hi completed_lo completed_hi crc_hi crc_lo
  ```

- `03` + `length+2` dummy → данные последнего успешного READ_BLOCK и CRC данных.
  Допускается только после готового статуса, совпадения sequence, opcode и длины.
  Следующая операция заменяет предыдущий результат; одновременно выполняется один запрос.

Статусы: 00 success, 01 busy, 02 opcode, 03 timeout, 04 Q5 failure,
05 readback mismatch, 06 controller fault, 07 CRC, 08 address/length,
09 locked, 0A duplicate sequence. `completed` — число успешно обработанных
байтов блока до ошибки; адрес ошибки равен `address + completed`.
У ID `result_lo` — производитель C2, `result_hi` — устройство A7/A8.
LOCK не прерывает уже принятую операцию.

## Бинарный USB CDC

Кадр Mac → RP2040:

```text
47 42 33 51  length_hi length_lo  payload  crc_hi crc_lo
 G  B  3  Q
```

Ответ имеет magic `GB3R`. CRC охватывает два байта длины и payload.
USB длина — big-endian, без magic, длины и CRC. Максимальный payload запроса —
1034 байта, ответа — 1036. Байты передаются без hex-кодирования и преобразования
переводов строк; значения 00/0A/0D допустимы внутри данных.

Payload запроса: одиночный `01` (версия), `02` (статус) либо целый SPI-запрос
операции со своим CRC. Мост проверяет запрос, отправляет его один раз, опрашивает
статус и проверяет sequence/opcode/CRC. Ответ операции — 10 байт статуса;
для успешного READ_BLOCK добавляются `length` байт данных и их SPI CRC.
Все три уровня CRC проверяются утилитой Mac.

Локальная ошибка моста — payload из одного байта: E1 SPI CRC, E2 кадр/CRC/длина,
E3 busy/sequence/count, E4 timeout. Время приёма USB-кадра — до 2 с,
ожидание операции FPGA — до 7 с, чтение ответа на Mac — до 10 с.
После повреждения USB-кадра вход отбрасывается до 100 мс тишины; внутри
оставшегося payload новые magic не ищутся. При подключении Mac выдерживает 2,2 с.
Автоматические повторы отсутствуют, особенно после потенциально принятой записи.
Ошибка требует остановки и выяснения состояния стенда.

## Частота и Flash

OSCH в `programmer` — 53,20 МГц. В LPF задано 64 МГц, но Map отклоняет
это значение для OSCH и применяет 53,20 МГц. Повторный TRACE пройден
на номинальной частоте; [подробности](TEST_PLAN.md#журнал-результатов).
SPI синхронизируется двумя регистрами. RTL-тест пройден при такте FPGA
около 42,55, 53,19 и 64 МГц с SPI 4 МГц. После Map требуется подтвердить
размещение буферов в EBR, использование ресурсов, пути SPI и внешней шины.
RTL-симуляция не подтверждает задержки после размещения и качество проводного монтажа.

Общий `mx29_bus` параметризован: в programmer один шаг чтения — 4 такта,
записи — 32. При 64 МГц от OE#/CE# до выборки проходит 187,5 нс;
WE# удерживается низким 500 нс. Значения по умолчанию сохранены для
`flash_bringup` на 2,08 МГц. Таймеры programmer пересчитаны: старт 16 млн тактов,
program timeout 128 тыс., erase timeout 192 млн. При 53,20 МГц это примерно
301 мс, 2,4 мс и 3,6 с соответственно.

Алгоритм и параметры: [Macronix MX29LV320E v1.3](https://www.macronix.com/Lists/Datasheet/Attachments/8542/MX29LV320E%20T-B,%203V,%2032Mb,%20v1.3.pdf),
таблицы AC и Q7/Q5 polling на рис. 20;
[настройки OSCH MachXO2](https://www.latticesemi.com/-/media/LatticeSemi/Documents/ApplicationNotes/MO/FPGA-TN-02157-3-0-MachXO2-sysCLOCK-PLL-Design-and-User-Guide.ashx?document_id=39080).
