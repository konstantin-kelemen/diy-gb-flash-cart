# PROGRAMMER: обработка блоков на RP2040, SPI v4

Конфигурация `game_programmer` использует короткие операции SPI v4.
RP2040 хранит блоки по 1..1024 байта, проверяет запрос USB, формирует отдельные
операции Flash, собирает прочитанные данные и вычисляет CRC ответа блока.
FPGA выполняет последовательности MX29LV320E, контролирует тайм-ауты Flash,
проверяет короткие SPI-кадры и управляет владением шиной. Мапперы и RTC работают
в FPGA; RP2040 не участвует в обращениях Game Boy к картриджу.

USB-интерфейс для существующей программы на компьютере остаётся `GB3Q/GB3R`,
версия 3.0, максимум 1024 байта. Его прежнее описание —
[PROGRAMMER_PROTOCOL.md](PROGRAMMER_PROTOCOL.md). Новая прошивка RP2040
требует SPI v4 и отклоняет FPGA с другой версией. Обновлять FPGA и RP2040 нужно
парой. Отдельный target `programmer` пока сохраняет SPI v3 и прежнюю RP2040-прошивку.

## SPI

Mode 0, MSB first, 4 МГц. CS# остаётся низким на весь кадр;
защитные интервалы до первого фронта, после последнего спада SCK и между кадрами
составляют не менее 2 мкс. Все значения op/key ниже шестнадцатеричные.

Запрос содержит 10 байтов, либо 11 для записи байта:

| Смещение | Содержимое |
|---|---|
| 0 | op |
| 1 | sequence, отличается от последнего принятого sequence |
| 2..4 | Адрес, big endian, `000000..3FFFFF` |
| 5..6 | Длина, big endian: 1 для `30/31`, иначе 0 |
| 7 | key: `A5` для `20/22`, иначе 0 |
| 8 | Данные, только для `31` |
| последние 2 | CRC-16/CCITT-FALSE заголовка и данных, high byte first |

Параметры CRC: polynomial `1021`, init `FFFF`, без отражения, xorout `0000`.
FPGA проверяет нулевой остаток после приёма CRC; отдельного регистра принятой
контрольной суммы нет. Команда фиксируется по подъёму CS# только после полного
кадра точной длины, при свободном исполнителе и разрешённом режиме.

| op | Операция |
|---|---|
| `01` | Запрос версии: затем 8 dummy bytes, ответ `47 42 46 43 04 00 01 00` |
| `02` | Запрос состояния: затем 10 dummy bytes, формат ниже |
| `20` | Разрешить изменение Flash, адрес 0, key `A5` |
| `21` | Снять разрешение |
| `22` | Удержать режим PROGRAMMER для блока, адрес 0, key `A5` |
| `23` | Освободить удержание после подтверждения состояния |
| `30` | Прочитать один байт, результат в состоянии |
| `31` | Записать один байт |
| `12` | Стереть сектор |
| `13` | Прочитать manufacturer/device ID |
| `14` | Вернуть Flash в read-array |

Состояние — 10 байтов: `50 sequence flags_status last_op result_lo result_hi
completed_lo completed_hi crc_hi crc_lo`. CRC покрывает первые 8 байтов.
`completed` равен 0 или 1. Для чтения байт возвращается в `result_lo`; команды
выгрузки буфера `03` в v4 нет. Снимок состояния фиксируется при приёме `02`.

Биты `flags_status`: младшие 4 — статус, `80` — удержание блока,
`40` — разрешён приём нового блока. Статусы: 0 — готово, 1 — занят,
2 — неизвестная команда, 3 — тайм-аут, 4 — ошибка Q5, 5 — ошибка проверки Flash,
6 — ошибка состояния исполнителя, 7 — CRC, 8 — адрес/длина, 9 — блокировка,
10 — повтор sequence. Последовательности SPI и USB независимы.

## Переключение режима и потеря RP2040

RP2040 получает удержание `22` до первой операции блока и освобождает его `23`
после последней. Пока удержание действует, появление питания Game Boy запрещает
новые блоки, но разрешает завершить текущий. В ответе на `23` бит `80` уже снят,
однако FPGA физически удерживает шину до окончания полного чтения состояния
(`02` + 10 dummy bytes). Частичное чтение не освобождает шину.

Если RP2040 пропал, удержание истекает после `2^20` свободных тактов (~19,7 мс
при 53,2 МГц). Пока выполняется операция Flash, отсчёт сброшен: запись/стирание
не обрываются. После истечения снимается разрешение изменения Flash.
Перед передачей шины Game Boy FPGA выполняет read-array cleanup; при ошибке
cleanup игровой режим не запускается.

RP2040 не повторяет команду при потере ответа: запись могла уже состояться.
При обрыве связи возможен частично записанный блок; это ошибка, а не успешное
завершение. Полный тайм-аут обработки запроса на RP2040 — 7 с.
Цена переноса обработки блоков — дополнительные обмены SPI на каждый байт;
скорость на аппаратуре ещё не измерена.

## Определение MBC1M

Для MBC1 ROM размером 1 МиБ FPGA сравнивает все 48 байтов `000104..000133`
и `040104..040133`. В FPGA хранится только текущий байт первой области;
встроенного логотипа или его хеша нет. Шаблоны целиком из `00` или `FF`
отбрасываются. Это эвристика по совпадению заголовков, а не проверка подлинности ROM.

## Проверки и сборка

```powershell
powershell -ExecutionPolicy Bypass -File fpga/tests/run.ps1
powershell -ExecutionPolicy Bypass -File fpga/targets/game_programmer/build.ps1
```

Скрипт FPGA останавливается при ошибке MAP, PAR или setup/hold TRACE.
В Diamond GUI у `game_programmer` отдельная стратегия `GameProgrammerArea`:
Area, 53,2 МГц, автоматическое назначение локального сброса на GSR отключено.
Ограничения внешней шины Game Boy не исчерпываются внутренним FREQUENCY NET clk;
проверки временных моделей не заменяют испытание платы.
