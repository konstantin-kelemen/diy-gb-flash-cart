# gbflash — Flash и сохранения через USB

`gbflash.py` читает и записывает память картриджа с через
USB CDC → RP2040 → FPGA:

- **Flash MX29LV320E:** 4 МиБ, ROM игры; поддерживаются Bottom Boot (`C2 A8`)
  и Top Boot (`C2 A7`).
- **F-RAM FM28V100:** 128 КиБ, сохранения; чтение, запись и заполнение диапазона.

Обмен с RP2040 выполняется блоками до 1024 байт с проверкой CRC.
Запись завершается чтением и побайтовой проверкой.

## Подготовка на macOS

Требуются Python 3, `pyserial` и совместимые прошивки FPGA/RP2040.
Game Boy должен быть выключен, картридж — в режиме PROGRAMMER.
Подключение определяется [схемой KiCad](../hardware/cartridge/cartridge.kicad_sch).

Все команды ниже выполняются из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install pyserial
ls /dev/cu.usbmodem*
```

Указать найденный порт:

```sh
FLASH_PORT=/dev/cu.usbmodem1234561
python host/gbflash.py --port "$FLASH_PORT" info
```

При успешном подключении выводится, например:

```text
MX29LV320E: C2 A8, Bottom Boot, PROGRAMMER
```

`info` проверяет идентификатор Flash и возвращает её в режим чтения массива;
содержимое памяти не меняется. Перед каждым подключением предусмотрена пауза
около 2,2 секунды для завершения возможного неполного USB-кадра.

Подготовка прошивок и полный сценарий испытания находятся в
[PROGRAMMER.md](../docs/PROGRAMMER.md). Внешний USB-протокол — v3;
текущая пара FPGA/RP2040 использует внутренний SPI v4. Обозначение `v3`
в сообщениях утилиты не означает, что требуется старая SPI-прошивка.

## Синтаксис

```text
python host/gbflash.py --port PORT COMMAND [OPTIONS]
```

`--port` обязателен и указывается перед командой. Адреса, длины и байт заполнения
принимаются в десятичной или шестнадцатеричной форме с префиксом `0x`.
Адреса и длины измеряются в байтах.

| Команда | Назначение и параметры |
|---|---|
| `info` | Определить тип Flash |
| `read FILE --length N [--address A]` | Считать диапазон Flash в новый файл; адрес по умолчанию `0`, длина обязательна |
| `write FILE --erase` | Стереть затронутые секторы, записать файл во Flash с адреса `0`, проверить чтением |
| `verify FILE` | Сравнить Flash с файлом начиная с адреса `0`, без записи |
| `fram-read FILE [--address A] [--length N]` | Считать F-RAM в новый файл; по умолчанию вся память |
| `fram-write FILE [--address A]` | Записать файл в F-RAM и проверить; адрес по умолчанию `0` |
| `fram-clear [--address A] [--length N] [--value V]` | Заполнить F-RAM байтом и проверить; по умолчанию вся память, байт `0xFF` |

Для `fram-read` и `fram-clear` пропущенный `--length` означает диапазон
от выбранного адреса до конца F-RAM. Для записи длина определяется размером файла.

```sh
python host/gbflash.py --help
python host/gbflash.py --port "$FLASH_PORT" fram-read --help
```

## Flash: ограничения и проверка

`write` и `verify` принимают непустой бинарный файл размером до
4 194 304 байт включительно. Расширение и заголовок ROM не проверяются.
Обе команды работают с адреса `0`; параметра смещения для них нет.

Флаг `--erase` при записи обязателен. Стираются целиком все секторы,
пересекающие файл, **включая остаток последнего сектора за концом ROM**.
Этот остаток остаётся заполненным `0xFF`; остальные секторы сохраняются.
Перед записью проверяется результат стирания, после неё — весь диапазон файла.
Отдельной команды стирания Flash нет.

Основной сценарий: полный дамп 4 МиБ → запись `.gb` → второй полный дамп
4 МиБ → побайтовое сравнение записанного диапазона второго файла с ROM.
[Точные команды полного цикла](../docs/PROGRAMMER.md#1-считать-все-4-миб-в-файл)
приведены в единой инструкции. Команда `verify` и встроенная проверка записи
не создают дамп и не заменяют сравнение двух сохранённых файлов.

## F-RAM: резервное копирование и восстановление

Считать сохранение, затем при необходимости восстановить его:

```sh
python host/gbflash.py --port "$FLASH_PORT" fram-read save.sav
python host/gbflash.py --port "$FLASH_PORT" fram-write save.sav
```

Запись не требует стирания и меняет только диапазон файла. Для независимого
сравнения после восстановления:

```sh
python host/gbflash.py --port "$FLASH_PORT" fram-read save-after.sav
cmp save.sav save-after.sav
```

`cmp` завершается с кодом `0` и без вывода при полном совпадении.
Эти команды предполагают полный исходный дамп 128 КиБ.

Пример чтения одного банка 8 КиБ и отдельная команда его очистки:

```sh
python host/gbflash.py --port "$FLASH_PORT" fram-read bank1.sav --address 0x2000 --length 0x2000
python host/gbflash.py --port "$FLASH_PORT" fram-clear --address 0x2000 --length 0x2000 --value 0xff
```

`fram-clear` перезаписывает выбранный диапазон. Дополнительного подтверждения
нет. Адреса F-RAM — физические смещения `0..0x1FFFF`, независимо от маппера.
Команды F-RAM не изменяют Flash; дамп сохранения не включает RTC.

## Результаты и ошибки

В терминале отображаются процент и количество обработанных байтов по фазам.
При перенаправлении вывода сохраняются начало и конец каждой фазы.
Успешные `write`, `fram-write` и `fram-clear` завершаются `Result: SUCCESS`,
`verify` — сообщением `Verified: … bytes; SUCCESS`.

- Код завершения `0` — успех; `1` — ошибка операции; `2` — ошибка аргументов CLI.
- `read` и `fram-read` не перезаписывают существующие файлы. После сбоя может
  остаться частичный дамп; для повторного чтения нужно другое имя файла.
- При несовпадении данных указываются адрес, ожидаемый и прочитанный байты.
- При тайм-ауте, ошибке CRC или потере ответа операция автоматически
  не повторяется. Часть записи могла уже выполниться; состояние проверяется чтением.
- `programmer locked` означает, что доступ к памяти не разрешён; проверить
  режим PROGRAMMER и состояние Game Boy.
- `FRAM is not supported…` означает отсутствие команд F-RAM в прошивке;
  нужна совместимая пара FPGA/RP2040 с этой возможностью.
- `No module named 'serial'` означает, что `pyserial` не установлен
  в используемом окружении Python.
